# Audit sistem dan UI NomCherry — 18 November 2026

## Kesimpulan
Implementasi belum layak dinyatakan siap produksi. Alur dasar berjalan dan semua tes bawaan lulus, tetapi ada masalah terverifikasi pada pemilihan cabang, validitas dashboard, pencegahan transaksi duplikat, penjualan stok kedaluwarsa, serta layout mobile.

Audit ini tidak mengubah source aplikasi atau database operasional. Pengujian menggunakan SQLite sementara yang dihapus setelah selesai. File probe dan screenshot tersedia di folder audit.

## Cakupan dan metode
- Aplikasi utama: `nomcherry-web`: routing, autentikasi/sesi, menu, checkout, stok, dashboard/laporan, settings, frontend aktif.
- `ProjekCafePBO/nomcherry-web`: pemeriksaan duplikasi; hash index-app.js identik dengan aplikasi utama pada saat audit. Bukan pengujian runtime kedua yang terpisah.
- Java Swing lama: pemeriksaan statis autentikasi, koneksi database, dan transaksi. Belum dikompilasi atau diuji dengan PostgreSQL.
- `template` bukan aplikasi operasional yang diuji.
- `npm run test:all`: lulus; 12 pemeriksaan verifikasi, 16 pemeriksaan fitur, suite keamanan/integrasi, 10 skenario E2E.
- Probe tambahan: Chrome headless, desktop 1440×900, tablet 768×900, mobile 390×900 dan 320×900. Pemeriksaan overflow pada overview, pos, orders, catalog, inventory, reports, settings. Tidak ada uncaught JavaScript error pada alur probe.
- Screenshot: desktop.png dan mobile-pos.png. Foto eksternal belum seluruhnya selesai dimuat saat capture; blok kosong bukan bukti bahwa semua URL rusak.
- Detector Impeccable dijalankan: satu warning pengulangan `Rp 0` dalam keranjang. Ditolak sebagai false positive karena subtotal, diskon, pajak, dan total memang membutuhkan nominal terpisah. Exit code 1 menandakan adanya finding; JSON berhasil dihasilkan.
- Audit tidak mengklaim sertifikasi WCAG, penetration test penuh, uji beban, validasi payment gateway, atau pengujian perangkat sentuh fisik. Dark mode dan kontras piksel belum diuji menyeluruh.

Prioritas: P1 berdampak besar pada operasi/ketepatan data; P2 gangguan atau kekurangan yang perlu ditangani; P3 pemeliharaan/polish. Tidak ada P0 yang terkonfirmasi pada alur dasar yang diuji.

## Temuan terurut

### 1. [P1] Pemilih cabang kembali ke cabang sesi
Bukti runtime: admin memilih CBG002, nilai selector setelah handler selesai adalah CBG001.
Lokasi: `nomcherry-web/public/js/index-app.js:1582` dan `:93–99`.
Penyebab: handler menetapkan STATE.branch lalu memanggil initSessionAndHeader(), yang membaca localStorage dan menimpa cabang dari user.id_cabang. Request berikutnya kembali memakai cabang lama.
Dampak: admin tidak dapat beralih cabang lewat UI dan berisiko membaca/mengelola data cabang yang salah.
Perbaikan: pisahkan hidrasi sesi awal dari render header; cabang aktif adalah state tersendiri dan hanya kasir yang terkunci ke cabang tugas. Uji perpindahan dua arah dan cabang pada request API.

### 2. [P1] Dashboard menampilkan grafik dan KPI statis sebagai data operasional
Lokasi: `nomcherry-web/public/js/index-app.js:186–232`, `:265`; `nomcherry-web/public/index.html:224–245`.
Grafik SVG beserta sumbu hari/7/30 hari memakai konstanta. Persentase kategori dan komposisi pesanan ditulis langsung di HTML. Updater mencari `ov-kpi-tx-count`, tetapi HTML menggunakan `ov-kpi-orders`; jumlah tetap 142 Struk walau screenshot menunjukkan 4 pesanan hari ini.
Dampak: kurva selalu terlihat meningkat meskipun pendapatan aktual kecil/nol; angka dashboard bertentangan.
Perbaikan: semua titik grafik, label, KPI, dan breakdown harus berasal dari agregasi API dengan periode/cabang yang sama. Tampilkan nol atau keadaan tanpa data bila kosong. Periksa pasangan ID updater dan HTML. Terkait antislop C-2: kelengkapan fungsional, bukan sekadar dekorasi data.

### 3. [P1] Checkout yang sama menghasilkan transaksi baru setiap kali
Bukti: dua POST /api/orders dengan payload sama sama-sama HTTP 200, menghasilkan PSN007 dan PSN008.
Lokasi: `nomcherry-web/public/js/index-app.js:1708–1795`; `nomcherry-web/src/controllers/orderController.js:createOrder`.
Tidak ada penguncian tombol selama request berlangsung dan tidak ada idempotency key server.
Dampak: klik berulang atau retry setelah respons jaringan hilang dapat menggandakan omzet dan pengurangan stok. Reproduksi membuktikan ketiadaan deduplikasi; bukan klaim bahwa semua klik pengguna pasti terduplikasi.
Perbaikan: status submitting di UI dan idempotency key unik per checkout, disimpan atomik dengan transaksi. Retry key sama harus mengembalikan hasil lama.

### 4. [P1] Stok kedaluwarsa masih diterima saat checkout
Bukti: stok cabang diberi tanggal 2000-01-01, checkout tetap HTTP 200 dan struk dibuat.
Lokasi: `nomcherry-web/src/controllers/orderController.js:createOrder`, blok validasi menu/stok; `stockController.js:62–87` hanya menghasilkan indikator.
Dampak: peringatan inventaris tidak menjadi batas penjualan.
Perbaikan: blokir stok kedaluwarsa di server memakai tanggal bisnis. Jika stok dikelola per batch, gunakan lot/FEFO dan jumlah layak jual, bukan satu tanggal untuk seluruh item.

### 5. [P1] Ringkasan memakai periode berbeda dan maksimal 500 transaksi
Lokasi: `nomcherry-web/public/js/index-app.js:255–307`, `:1187`, `:1294–1315`; `nomcherry-web/src/controllers/orderController.js:getAll`.
fetchOrders tidak memberi filter tanggal/paginasi. API membatasi 500 baris; widget pembayaran bertuliskan Hari Ini menghitung seluruh baris yang dimuat, sedangkan omzet utama memakai agregat hari ini. Total 7/30 hari juga dihitung dari subset 500 tersebut.
Dampak: rekap harian berbeda cakupan dan total periode terpotong saat transaksi meningkat.
Perbaikan: agregasi server per periode/cabang, terpisah dari daftar berpaginasi. Jangan menghitung total bisnis dari satu halaman data.

### 6. [P1] Pajak historis dihitung ulang memakai tarif saat ini
Lokasi: `nomcherry-web/public/js/index-app.js:303–310`.
Nett dan pajak dihitung dengan grossTotal / (1 + STATE.taxRate / 100), bukan menjumlahkan pajak tersimpan pada transaksi.
Dampak: mengubah tarif pajak di settings dapat mengubah rekap transaksi lama walau struk tidak berubah.
Perbaikan: SUM(subtotal - diskon), SUM(pajak), SUM(total) dari transaksi tersimpan; tarif transaksi harus tetap menjadi snapshot historis.

### 7. [P1] Layout tablet/mobile melebar di luar viewport
Bukti seluruh tujuh view: viewport 768 → scrollWidth 824; viewport 390 dan 320 → scrollWidth 541.
Lokasi: `nomcherry-web/public/css/cofra-theme.css:.top__right`, `.top__crumbs`, breakpoint `:2584`; struktur topbar di index.html.
Dampak: halaman dapat digeser horizontal, header/aksi keluar layar. Screenshot mobile menunjukkan area kosong di kanan.
Perbaikan: ukur elemen penyebab overflow; ringkas breadcrumb/aksi header, tempatkan branch selector pada baris tersendiri, gunakan min-width:0 pada grid/flex yang tepat. Jangan menutup masalah dengan overflow:hidden global.

### 8. [P1] Pembuatan menu menggandakan stok awal ke semua cabang
Lokasi: `nomcherry-web/src/controllers/menuController.js:create`, loop INSERT stok_cabang untuk seluruh cabang.
Pembuatan menu dengan stok awal N memasukkan N ke setiap cabang, tetapi log stok awal hanya dibuat untuk branchId. Ini terlihat langsung dari implementasi; belum diuji dengan alur distribusi stok riil.
Dampak: input stok di satu cabang menciptakan stok tersedia di cabang lain tanpa mutasi asal yang cocok.
Perbaikan: pisahkan katalog global dari stok; isi N hanya di cabang tujuan, cabang lain nol, atau wajibkan alokasi eksplisit per cabang dan log masing-masing.

### 9. [P1] Akun demo otomatis dibuat tanpa pemisahan mode produksi
Lokasi: `nomcherry-web/src/database/db.js:325–350`.
Database kosong otomatis memperoleh akun dengan password tetap yang juga digunakan tes/dokumentasi. Hash password tidak menghilangkan risiko kredensial default yang diketahui.
Dampak: instalasi baru yang dibuka ke jaringan dapat memiliki akun masuk yang dapat ditebak.
Perbaikan: seed demo hanya lewat flag eksplisit development/test; produksi memakai bootstrap admin dengan rahasia acak dan wajib ganti password. Tambahkan alur perubahan/reset password karena API saat ini hanya menyediakan tambah/hapus pengguna.

### 10. [P2] Keranjang mobile berada setelah semua produk
Bukti screenshot mobile-pos.png: katalog satu kolom berisi 24 produk mendahului panel pembayaran; dokumen capture setinggi 8768 px.
Lokasi: `nomcherry-web/public/css/cofra-theme.css:2552–2580`, `.pos-layout`, `.pos-cart-card`.
Dampak: pengguna menambahkan barang di atas lalu perlu menggulir sangat jauh untuk melihat total/membayar.
Perbaikan: ringkasan keranjang persisten di bawah dengan jumlah/total dan tombol Buka Keranjang; pembayaran di drawer/sheet yang mudah ditutup, memperhitungkan bottom navigation.

### 11. [P2] Fokus keyboard dapat keluar dari modal
Bukti: modal menu memiliki role dialog dan aria-modal=true, tetapi setelah 14 Tab fokus berpindah ke luar modal.
Lokasi: `nomcherry-web/public/js/index-app.js:655–659`, handler Escape `:1524`.
focusModal hanya memindahkan fokus awal; tidak ada focus trap atau pengembalian fokus saat tutup. Escape hanya menghapus class.
Dampak: pengguna keyboard dapat menjalankan kontrol latar sementara dialog terbuka dan kehilangan posisi setelah tutup.
Perbaikan: dialog native atau utilitas bersama dengan trap, inert latar, Escape, dan restore focus ke pemicu. Jalankan verifikasi keyboard pada seluruh modal dan drawer.

### 12. [P2] Kasir/owner melihat form settings yang tidak dapat disimpan
Lokasi: `nomcherry-web/public/js/index-app.js:ROLE_VIEWS`, `:2329`; `nomcherry-web/src/routes/api.js` PUT /settings hanya admin/manager.
Dampak: pengguna mengisi konfigurasi sebelum mendapat penolakan 403.
Perbaikan: settings readonly sesuai peran, pisahkan pengaturan akun/tema dari konfigurasi bisnis, tampilkan keterangan akses sebelum interaksi.

### 13. [P2] Tanggal kedaluwarsa memakai UTC, berbeda dari tanggal bisnis
Lokasi: `nomcherry-web/src/controllers/stockController.js:62–84`.
todayStr memakai toISOString(), sedangkan laporan menggunakan dateService. Di Jakarta sebelum 07.00 WIB, tanggal UTC masih hari sebelumnya.
Dampak: status kedaluwarsa dapat terlambat berubah dibanding tanggal operasional.
Perbaikan: gunakan dateService yang sama di semua modul dan validasi format/kalender tanggal pada input API; uji sekitar pergantian hari.

### 14. [P2] Struk cabang menggunakan konfigurasi global dan nilai form yang belum disimpan
Lokasi: `nomcherry-web/public/js/index-app.js:661–665`; `nomcherry-web/src/services/settingsService.js:SETTING_KEYS`.
Struk mengambil nama/alamat/footer dari DOM settings; settings disimpan tanpa kunci cabang. Respons checkout sebenarnya sudah membawa informasi cabang.
Dampak: cabang berbeda dapat mencetak alamat yang sama; edit settings yang belum tersimpan bisa memengaruhi cetak. Perbaiki masalah switch cabang terlebih dahulu untuk menguji alur multi-cabang penuh.
Perbaikan: gunakan data struk dari server dan snapshot identitas cabang per transaksi; settings cabang harus dibedakan dari settings global.

### 15. [P2] Data antar terminal tidak tersinkron otomatis
Lokasi: `nomcherry-web/public/js/index-app.js:syncWithBackend` dan seluruh pemanggilnya.
Sinkronisasi terjadi saat inisialisasi/aksi lokal, tanpa polling, SSE, atau WebSocket. Beberapa copy menyatakan real-time, otomatis, atau shift aktif.
Dampak: terminal dapur/kasir kedua dapat tetap menampilkan antrean dan stok lama sampai reload/aksi baru. Guard stok server tetap membantu saat checkout.
Perbaikan: refresh berkala atau event server, indikator terakhir diperbarui/offline, serta retry yang aman. Status shift/koneksi harus berasal dari keadaan sebenarnya.

### 16. [P2] Fitur member ditampilkan sebagai navigasi aktif tetapi belum tersedia
Lokasi: `nomcherry-web/public/js/index-app.js:1088–1091`, `:2300–2306`.
Daftar member kosong dan tombol tambah hanya menghasilkan toast tentang aturan tier/poin yang belum disetujui.
Dampak: navigasi dan tombol menjanjikan alur yang tidak dapat diselesaikan.
Perbaikan: tandai sebagai belum tersedia dan nonaktifkan CTA atau sembunyikan sampai aturan bisnis dan penyimpanan siap. Diskon Member/VIP di POS juga perlu kebijakan otorisasi/kelayakan yang jelas.

### 17. [P2] Pesan gagal memakai ikon sukses yang sama
Lokasi: `nomcherry-web/public/js/index-app.js:71–85`.
showToast selalu menambahkan simbol centang, termasuk pesan transaksi gagal/akses ditolak; toast hilang setelah 3,2 detik.
Dampak: feedback visual berlawanan dengan hasil tindakan dan pesan penting mudah terlewat.
Perbaikan: tipe success/error/warning, ikon/warna sesuai, error checkout persisten di dekat kontrol, dan announcement yang tepat.

### 18. [P2] Java lama memakai password langsung dan stok bisa negatif
Lokasi: `ProjekCafePBO/ProjekCafePBO/src/dao/PenggunaDAO.java:23–32`; `dao/PesananDAO.java:updateStokMenu`; `service/TransaksiService.java:tambahKeKeranjang` dan checkout.
Login membandingkan kata_sandi langsung dalam SQL dan create/update menyimpan nilai password dari model. Pengurangan stok tidak memiliki syarat stok >= jumlah; tambah item berulang hanya membandingkan jumlah tambahan, bukan total keranjang. Fungsi cekStokTersedia tidak dipanggil checkout.
Dampak bila aplikasi lama masih digunakan: kredensial tidak terlindungi oleh hashing dan penjualan dapat membuat stok negatif. Transaksi SQL sudah memiliki commit/rollback, namun tidak memperbaiki validasi tersebut.
Perbaikan: tentukan apakah Java diarsipkan atau didukung; jika didukung, hash password dengan migrasi dan lakukan decrement bersyarat dalam transaksi. Temuan statis, belum direproduksi terhadap PostgreSQL.

### 19. [P3] Dua salinan web dan modul frontend tidak aktif meningkatkan risiko salah edit
Lokasi: `nomcherry-web`, `ProjekCafePBO/nomcherry-web`; `nomcherry-web/public/index.html` hanya memuat js/index-app.js.
File app.js, pos.js, dashboard.js, users.js dan lainnya tidak menjadi entry frontend aktif pada index saat ini. Git berada di ProjekCafePBO, sementara launcher root menjalankan salinan di luar repository tersebut.
Dampak: perbaikan dapat dilakukan pada file/salinan yang tidak dijalankan atau tidak tercatat version control.
Perbaikan: tetapkan satu root aplikasi yang versioned, satu launcher, arsipkan legacy secara jelas, lalu hapus modul mati setelah referensinya diverifikasi.

## Hal yang sudah baik
- Session cookie HttpOnly, SameSite Strict, tanda tangan HMAC, pencabutan session server, serta pemeriksaan role pada API.
- Query terparameterisasi, CSP dan header keamanan tersedia.
- Checkout web memakai transaksi SQL dan decrement stok bersyarat sehingga rollback dapat menjaga konsistensi ketika stok berubah.
- Nama/harga item disalin ke detail pesanan, membantu mempertahankan histori setelah katalog berubah.
- Pengujian bawaan memakai database sementara; sebagian alur akses kasir dan logout sudah diuji E2E.
- Banyak nilai dinamis di frontend aktif di-escape; produk memiliki dukungan keyboard dan modal memiliki semantik dialog.

## Urutan perbaikan yang disarankan
1. Cabang aktif, stok kedaluwarsa, transaksi idempotent, alokasi stok awal, dan bootstrap akun produksi.
2. Agregasi dashboard dari server, ID KPI, grafik aktual, periode konsisten, pajak historis.
3. `$impeccable adapt`: overflow dan akses keranjang mobile.
4. `$impeccable harden`: fokus modal, hak akses form, error state, sinkronisasi dan retry.
5. `$impeccable clarify`: status demo/payment/shift/member, label periode dan indikator data terbaru.
6. `$impeccable polish`: konsistensi detail UI setelah fungsionalitas diperbaiki.
7. Ulangi audit dan tambahkan regresi terarah untuk temuan 1–14. Tes saat ini lulus tetapi belum membuktikan kondisi-kondisi tersebut.

Perbaikan dapat dikerjakan per temuan atau per kelompok prioritas. Audit ini tidak menerapkan perubahan aplikasi.
